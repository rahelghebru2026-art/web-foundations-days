# Day 8 Reflection

The most difficult concept in this course was designing a system that remains correct and reliable when many users make requests at the same time. At first, it was easier to focus on writing API endpoints and creating database tables than to think about what happens when two users try to perform the same operation simultaneously. I improved my understanding by studying transactions, database constraints, request flows, caching, and the responsibilities of different architecture components. Working on the QuickNotes System Design capstone also helped me understand the importance of completing every part of a design and checking that the implementation matches the documentation.

Based on the feedback I received on my capstone, I would improve my attention to completeness and final verification. Although my API design and data model received positive feedback, my submission had incomplete sections in `api.js` and `docs/architecture.md`, as well as formatting issues in `index.html`. I learned that producing good technical content is not enough; I must also check that every required function, event listener, documentation section, and file is included in the final version pushed to GitHub. For future projects, I will use a checklist and test the submitted version rather than assuming that my local files and repository are identical.

Next, I want to strengthen my knowledge of backend development with Python, SQL, REST APIs, and automated testing. I also want to practice building projects that use authentication, database transactions, and reliable error handling. These skills will help me progress toward becoming a software developer and prepare me for more advanced work in software engineering and machine learning.
